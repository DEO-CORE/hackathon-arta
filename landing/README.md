# ARTA · Landing

Адаптивный интерфейс на React 19, Tailwind CSS 4 и Vite. Добавлен отдельно от существующего Flutter-клиента в `frontend/`.

## Запуск

Требуется Node.js 22.12+ или 24+. Из корня репозитория:

```powershell
cd landing
npm ci
npm run dev
```

Откройте адрес `Local`, который напечатает Vite. Обычно это `http://127.0.0.1:5173`; если порт занят, Vite выберет следующий.

```powershell
npm run build
npm run preview
```

Результат сборки — `dist/`. Сайт не опубликован, коммит и push не выполнены.

## Что работает

- Главная с описанием ARTA и переходами в рабочие сценарии.
- Статьи в диалогах, раскрывающиеся вопросы и помощь с переходом в нужный сценарий.
- Карусель «Как это работает»: карточки перелистываются по дуге с изменением глубины и мягкой остановкой; текст появляется последовательно, номер шага прокручивается. Доступны стрелки, свайп на телефоне и клавиши ←/→. Быстрые повторные нажатия продолжают движение из текущего положения; изменение размера окна завершает переход в правильной позиции.
- Появление секций при прокрутке, отклик карточек и кнопок. Учитывается системное уменьшение анимации (`prefers-reduced-motion`).
- Регистрация в два шага: профиль → email и пароль. Покупателю нужны имя и город, продавцу — организация, город и направление работы. Значения сохраняются при смене роли и возврате между шагами. Вход, восстановление и смена пароля с валидацией; серверная интеграция описана в `INTEGRATION.md`.
- Каталог: поиск, материал, город, сортировка, пустое состояние, дополнительные карточки.
- Карточка материала, параметры, остаток, предварительный расчёт стоимости заявки.
- Создание партии с валидацией, фото, направлениями применения и подтверждением характеристик человеком.
- Фото JPEG/PNG/WebP до 10 МБ и 20 Мп: декодирование, предпросмотр, предпросмотр; в режиме API исходный файл загружается на сервер.
- Путь заявки: заявка → резерв → передача → получение → отдельное подтверждение использования.
- Отмена до передачи, освобождение резерва, проверка остатка, отсутствие двойного учёта использования.
- В режиме demo: localStorage, обновление между вкладками и сброс через подтверждение.
- Мобильное меню, клавиатурное управление диалогами, страница 404.
- Переключатель RU / KY / EN в шапке: русский, кыргызский и английский интерфейс. Выбор сохраняется в браузере и синхронизируется между вкладками.
- Скруглённое меню языков с анимацией, отметкой выбора и управлением стрелками, Home/End, Enter и Escape. Tab продолжает навигацию по странице; нажатие снаружи закрывает меню.
- Логотип `arta.` набран локальным Montserrat 700. Футер — светлая скруглённая карточка с колонками ссылок и крупным знаком MADE BY DEO по центру. Исходный SVG: `public/images/made-by-deo.svg`.
- Все десять секций главной страницы оформлены белыми скруглёнными блоками на общем фоне `#f1f2ed`, с одинаковой шириной и промежутками, как футер. Геометрия и адаптивные настройки вынесены в `src/styles/home-blocks.css`, подключённый после основных стилей в `src/main.jsx`.
- Такой же стиль применён к каталогу, карточке ткани, размещению, заявкам, всем четырём экранам аккаунта и состояниям «не найдено». Общие классы `page-blocks` / `page-block` и адаптивные настройки этих страниц находятся в `src/styles/page-blocks.css` и используют те же параметры рамок, что главная и футер.

## Языки

Переведены навигация, кнопки, заголовки, формы, подсказки, ошибки, диалоги, статусы, демо-материалы и справочные тексты. `lang` документа, заголовок вкладки, формат дат и чисел меняются вместе с языком. По умолчанию используется русский.

Смена языка не перезагружает страницу, не сбрасывает шаг регистрации, поля или фильтры. Поиск демо-материалов понимает названия на всех трёх языках. Введённые пользователем названия, описания, города и контакты не переводятся и не перезаписываются.

Словари находятся в `src/i18n/common.js`, `home.js`, `forms.js`, `content.js`. Каждая запись содержит `[русский исходник, английский перевод, кыргызский перевод]`. Для нового текста интерфейса используйте `t("Исходный текст")` из `useI18n()` и добавьте запись в словарь. Параметры передаются отдельно: `t("Открыть: {{0}}", { 0: name })`. Имена пользователя внутри параметров не переводятся. Коды API, URL и сохранённые данные не зависят от языка.

## Единый бэкенд

По умолчанию сайт работает с API из `backend/`: регистрация, HttpOnly-сессия, личный покупатель без организации, каталог, загрузка фото, публикация, заявки и серверные показатели. Анализ фото подключён к OpenAI, восстановление пароля — к SMTP. Их ключи и настройки задаются только на сервере.

Подробные команды запуска, контракты, переменные окружения и проверки — в [INTEGRATION.md](INTEGRATION.md). Перед запуском сайта примените миграции и запустите API на 8000. Vite проксирует `/api` к нему. Используйте фиксированный порт 5173, который разрешён в CORS.

Демонстрация включается отдельно через `VITE_DATA_MODE=demo`. Ошибки API никогда не переключают сайт на демоданные. Пароли и токены не записываются в браузерное хранилище. Подтверждённое использование учитывается отдельно от передачи и получения.

## Проверки

```sh
npm test
npm run build
```

Реальный браузерный сценарий запускается через `npm run test:e2e` против отдельного API с тестовой БД; подготовка описана в [INTEGRATION.md](INTEGRATION.md). Реальную доставку SMTP и ответы OpenAI нужно дополнительно проверить после заполнения настроек провайдеров.
