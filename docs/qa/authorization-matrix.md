## 1. Допущения (подтвердить по `docs/api.md` после CON-01)

| ID | Допущение |
|---|---|
| A-1 | Без токена или с просроченным/подделанным токеном — 401 на всех маршрутах, кроме `/auth/register`, `/auth/login`, `/health`. |
| A-2 | Неверная роль для маршрута (например, buyer вызывает `POST /materials`) — 403. |
| A-3 | Чужой объект, существование которого скрывается (черновик, план, анализ, фото, чужая заявка) — 404. Если api.md выберет 403, меняется только ожидаемый код; единый выбор должен быть одинаковым для всех ресурсов. |
| A-4 | Для чужих объектов ответ 404 не должен отличаться по телу и времени от ответа для несуществующего UUID (нет утечки существования). |
| A-5 | Один пользователь — одна организация. Recycler = роль `buyer` + `organizations.activity_type = recycler`; отдельной роли нет. |
| A-6 | `admin` не назначается через публичную регистрацию. Права admin в MVP — только ручная модерация; объём прав фиксируется в api.md. |

## 3. Матрица прав: ресурс × роль × действие

Обозначения: OK — разрешено (2xx), 401, 403, 404 — ожидаемый код; «свой» = объект своей организации; «чужой» = другой организации; «уч.» = участник соответствующей сделки.

## 5. Проверка полей ответа (минимизация данных)

| ID | Проверка | Ожидание |
|---|---|---|
| FLD-01 | Buyer читает published партию | нет контактов продавца, нет `confirmed_by`, нет внутренних объектов анализа и ключей Storage |
| FLD-02 | Buyer читает партию после confirmed резерва, где он участник | контакты продавца доступны только участнику |
| FLD-03 | Список заявок продавца | нет контактов покупателей, не участвующих в сделке |
| FLD-04 | Ответ любого маршрута | нет `password_hash`, JWT, service-role ключа, постоянного URL фото |
| FLD-05 | Ответ об ошибке | нет traceback, SQL, путей; есть `code`, `message`, `request_id` |
