## 0. Правила

### Статусы
- PASS — проверено фактическим касанием/вводом на устройстве, результат совпал с ожидаемым. Тесты `flutter test` и просмотр кода не дают PASS.
- FAIL — воспроизведено на устройстве расхождение; заводится дефект (ID, шаги, скриншот/лог, сборка).
- BLOCKED — не выполнено из-за внешней зависимости (указать какой).
- NOT IMPLEMENTED — функции нет в сборке (подтверждено осмотром экрана).
- NOT TESTED — не выполнено (указать причину).
- SIMULATED — суффикс для всех результатов AI в демо: результат из фикстуры, не живой AI. PASS (SIMULATED) подтверждает только UI и контракт, не качество AI (MB-03 из `mobile-test-plan.md`).

## 10. Риски

1. Сценарии DEMO-01..09 зависят от реализации локального хранения фото и данных во flutter-developer; если данные только в памяти, DEMO-07 упадёт, а DEMO-02 нельзя проверить. Нужно решение владельца, что именно демо должно сохранять, до прогона.
2. Демо-AI — фикстура: PASS в разделе 3 не подтверждает качество и работоспособность реального AI и Storage (BLK-02, BLK-03); риск, что результат будет воспринят как проверка живого провайдера. Режим должен называться честно на экране и в отчёте. AI-SIM-07 без переключателя сценария не проверяется.
3. Приватность: на телефоне есть личные уведомления и аккаунт Google; один неудачный скриншот раскроет их (в v1 это уже произошло). Нужны отключённые уведомления и проверка каждого файла до передачи. Дополнительно прогон выполняется вручную через `adb input`, что нестабильно по координатам и может дать ложные FAIL/NOT TESTED.
