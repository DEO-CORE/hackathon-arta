## 1. Утверждённый порядок ответов
1. 401 — нет или недействительный токен.
2. 404 — приватный ресурс недоступен вызывающему (чужая организация, несуществующий, неверный UUID, чужой вложенный ID). Существование не раскрывается.
3. 403 — ресурс доступен, но операция запрещена роли/правам (например, buyer публикует свою доступную для чтения сущность или роль без права).
4. 422 — неверное состояние/данные бизнес-правил, только после успешной авторизации (publish без фото, неверная версия формата и т. п.).
5. 409 — конфликт состояния/версии/запаса после 1–4.
Проверка порядка: неавторизованный не должен видеть разницу между «нет такого» и «чужое»; ошибка бизнес-состояния (422/409) не возвращается чужому пользователю вместо 404.

Уточнение оркестратора: партия недоступна покупателю (чужой черновик, скрытая) — 404 раньше всего; видна и доступна на чтение (опубликована) — 403. Противоречия нет, порядок 404 → 403 → 422 прежний. Ниже старая формулировка оставлена для истории.

Правило: buyer на enterprise-маршрутах, где ресурс заведомо недоступен ему по типу (публикация партии), — по утверждённому порядку: ресурс не принадлежит его организации, т.е. приватный и недоступный, ответ 404; 403, если партия ему доступна для чтения (опубликована) и операция запрещена. Это место вызвано формулировкой задачи («публикация покупателем — 403»); обязательно сверить с backend-engineer, какой ответ ожидается для чужой неопубликованной партии (404) и для опубликованной (403). Тест на оба случая.
