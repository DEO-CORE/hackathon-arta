# ARTA — план тестирования (QA-01)

Статус: план. Код продукта и `docs/api.md` на момент составления отсутствуют; ни одна проверка не запускалась. Сроки и готовность пунктов обновляются по факту запуска. Не отмечать «пройдено» без запуска и сохранённого вывода.

Связанные документы: `authorization-matrix.md`, `race-cases.md`, `invariants.md`; `docs/orchestration/QUALITY_GATES.md`; `CLAUDE.md` §15, §16.

## 1. Уровни тестирования

| Уровень | Что проверяет | Среда | Владелец | Расположение | Инварианты, которые охватывает |
|---|---|---|---|---|---|
| Unit | чистая логика без БД и сети: совместимость, скоринг, solver, формулы аналитики, валидация AI JSON, машина состояний | pytest, без БД | backend / optimization / ai | `backend/tests/unit/` | INV-50..62 (расчёт), INV-36, INV-37 (формулы), INV-09 (Decimal) |
| Integration | API + SQLAlchemy + отдельная PostgreSQL: auth, права, публикация, upload, версии, жизненный цикл заявок | pytest, отдельная БД `*_test`, Alembic до head | backend | `backend/tests/integration/` | INV-01..08, INV-72..75, часть матрицы авторизации |
| Race | конкуренция независимых сессий на PostgreSQL; идемпотентность при параллельных повторах | pytest + потоки/asyncio, PostgreSQL | QA | `backend/tests/race/` | INV-01, 02, 05, 11, 20, 24; все RC-кейсы |
| Contract | живое API соответствует `docs/api.md`: коды 201/202/401/403/404/409/422/429, конверт ошибки, DTO, decimal-строки, отсутствие traceback | запущенный сервер или TestClient + сверка с OpenAPI/api.md | QA | `backend/tests/contract/` | INV-09, INV-74, FLD-01..05 |
| E2E API | полный путь MVP по HTTP на свежей БД; после шагов проверка инвариантов | pytest, свежая БД + seed | QA | `backend/tests/e2e/` | INV-01..08, 20..41 |
| E2E UI | один сценарий Flutter → FastAPI → PostgreSQL | `flutter test integration_test`, только если платформа настроена; иначе документированный ручной прогон | QA | `frontend/integration_test/` | видимость остатка/409, разделение прогноз/факт |
| Widget (справочно) | формы, состояния AI, 409 | flutter test | flutter-developer | `frontend/test/` | UI-подписи |
| Ручной | демо-прогон по `docs/demo.md`, режим fallback AI | свежая БД | QA | `docs/qa/` (журнал) | Gate 4 |

Принципы: тесты на риски и инварианты, а не на повторение реализации; БД тестов отдельная, миграции только на тестовой БД; SQLite не заменяет PostgreSQL; фикстуры синтетические, без реальных контактов; продуктовый код ради теста не меняется.

## 6. Окружение и данные

| Тема | Правило |
|---|---|
| БД | `ARTA_TEST_DATABASE_URL`-подобная отдельная переменная (имя уточнить по README бэкенда); перед запуском тест проверяет, что имя БД оканчивается на `_test`, иначе прерывается |
| Данные | синтетические, фиксированные UUID и seed; метка «синтетические данные»; без реальных контактов |
| AI | mock-провайдер в тестах; live provider проверяется отдельно, результат маркируется live/mock |
| Storage | тестовый bucket или заглушка адаптера; секреты не в репозитории |
| Время | UTC; тесты, зависящие от exp токена, используют управляемые часы |
| Нагрузка | p95 ≤ 1 с для обычных API измеряется отдельным замером на тестовом наборе; AI и solver — отдельно; цель не заявлять без замера |

## 7. Классификация дефектов

| Серьёзность | Определение | Примеры |
|---|---|---|
| blocker | нарушает безопасность, баланс, или ломает путь MVP | отрицательный остаток, доступ к чужому объекту, двойная транзакция |
| major | функция работает неверно, есть обход | неверный код ответа, прогноз в выручке |
| minor | не влияет на путь | текст, редкий краевой случай |
| cosmetic | оформление | надписи, выравнивание |

Журнал дефектов: `docs/qa/issues.md` (создаётся при первом найденном дефекте; поля: ID, серьёзность, область, шаги, ожидаемое, фактическое, вывод/лог, коммит/ветка).

## 8. Известные ограничения плана

| Ограничение | Следствие |
|---|---|
| `docs/api.md` и код отсутствуют | коды ответов и права admin взяты из `CLAUDE.md` и помечены допущениями; после CON-01 сверить |
| Репозиторий не под git | поле «коммит/ветка» в отчётах — «не определено» |
| Права admin не определены в MVP | кейсы AD помечены «по api.md» и не считаются покрытыми |
| Live Vision и Supabase зависят от BLK-02/03 | проверки с ними — «не запущено» до снятия блокеров |
| Flutter integration_test требует настройки платформы | иначе документированный ручной прогон |
