## 1. Что проверяем визуально

Общие правила для каждой контрольной точки: нет жёлто-чёрной полосы overflow; нет обрезанного текста без многоточия/переноса; отступы кратны токенам (без "магических" значений); русский текст.

## 2. Автоматическая часть: golden-тесты

Область: компоненты из `frontend/lib/core/ui/` и P0-экраны в демо-режиме. Фактическое наличие каталога и демо-режима проверить перед написанием; если их нет, не писать голдены "вслепую", завести дефект.

- Размеры: 360x640 и 412x915 dp, devicePixelRatio фиксировать (рекомендуется 1.0 для стабильности размера файлов, либо 2.625 как у эталонного устройства, но одно значение на весь набор). Светлая тема.
- Каждый экран: состояния loading, empty, error, success (данные из синтетических фикстур, помеченных демо). Данные не из сети; провайдеры переопределять fake-репозиториями.
- Текст масштаба 1.0 и 1.3 для ключевых экранов (вход, карточка, создание).
- Строка длиной 80 символов в названии партии: отдельный голден каталога и карточки.
- Шрифты: golden-файлы зависят от шрифтов платформы, поэтому Roboto (и кириллические начертания) загружать явно через `FontLoader` в `setUpAll` из файлов, лежащих в репозитории (не из системы), иначе эталоны будут различаться между машинами и заменятся на "Ahem"-квадраты. Без явной загрузки голдены считать недействительными.
- Анимации: `pumpAndSettle` с таймаутом, индикаторы прогресса заменять на статичные кадры.
- Файлы эталонов хранить рядом с тестами (`test/goldens/`). Принадлежность тестов: flutter-developer; QA ревьюит и может добавлять тест-only изменения с явной пометкой в отчёте.
- Обновление: `flutter test --update-goldens` запускается только осознанно, для конкретных файлов (`--update-goldens path/to/test.dart`), после ручного просмотра diff. В отчёт записывается: какие эталоны обновлены, причина (намеренное изменение дизайна, ссылка на задачу), кто просмотрел. Массовое обновление "чтобы позеленело" запрещено.
- Голдены ловят пиксельные изменения, но не заменяют проверки раздела 3 (клавиатура, реальные шрифты устройства, системные вставки).

## 4. Доступность

Проверка по токенам до пикселей: контраст считать по значениям цветов темы (текст на фоне, текст на кнопке, текст ссылок, иконки статусов, плейсхолдеры, помеченные ошибки). Результаты считать формулой WCAG, не на глаз.
- Порог WCAG AA: обычный текст 4.5:1, крупный текст (от 24 px или 18.66 px жирный) и значимые элементы интерфейса 3.0:1. Отдельно проверить оранжевый текст на светлом фоне (ссылки, "Изменить", "Заполнить") и тёмный текст на оранжевой кнопке; серый текст чипа "Черновик/В архиве".
- Размеры касания: не менее 48x48 px (в dp 48 при плотности устройства; на устройстве с density 420 это 126 px) для кнопок, чипов, иконок, ссылок. Проверять `tester.getSize` в виджет-тестах и визуально на устройстве.
- Подписи полей видимы всегда (не только hint); у иконочных кнопок есть `tooltip`/`Semantics.label` (выход, показать пароль, назад).
- Статусы (черновик, доступно, зарезервировано, в архиве, подтверждено) передаются текстом и иконкой, не только цветом; проверить в режиме оттенков серого.
- Ошибки: озвучиваются (Semantics liveRegion / `SemanticsService.announce`) и связаны с полем; не только красная рамка. Проверка: TalkBack на устройстве, затем виджет-тест на наличие семантики.
- Масштаб текста 1.3 без overflow; порядок фокуса при клавиатурной навигации логичен.

## 5. Критерии прохождения

Блокируют закрытие фазы:
- любой overflow (виджет или жёлто-чёрная полоса) на 360x640 или 412x915;
- пропавшее или недостижимое главное действие экрана (в том числе перекрытие кнопкой "Создать партию" или клавиатурой);
- контраст текста или кнопки ниже порога (4.5 обычный, 3.0 крупный/UI-элемент) по токенам;
- потеря введённых данных при открытии клавиатуры, повороте или возврате;
- зона касания основного действия менее 48 px;
- статус или ошибка передаются только цветом;
- пустая секция без состояния (например "Анализ ИИ" без содержимого), если она влияет на путь MVP;
- отсутствие метки "демо"/синтетические данные там, где она требовалась;
- голдены писались без явной загрузки Roboto или эталоны обновлены без записи причины;
- не пройдены `dart format`, `flutter analyze`, `flutter test`.

Допустимы как P2 (фиксируются в журнале, не блокируют):
- разница в 1-2 px в отступах без нарушения токенов и без визуального дефекта;
- декоративные отличия иконок, радиусов, теней;
- неоптимальная, но не вредная плотность на широком экране;
- отсутствие анимации/skeleton при корректном индикаторе загрузки;
- единичные расхождения форматирования подписей при сохранении единиц и читаемости.

Вердикт по каждой точке: пройдено / не пройдено / не запускалось (с причиной). Непроверенное не отмечается пройденным.
