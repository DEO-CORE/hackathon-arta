# ARTA: содержание слайдов (ЧЕРНОВИК)

Дата: 2026-11-08. Метки на слайдах: ФАКТ / ВТОРИЧНО / ДОПУЩЕНИЕ / ПРОЕКЦИЯ / ДЕМО / ТРЕБУЕТ ПРОВЕРКИ (определения в `arta-pitch-deck-plan.md`). Формата PPT/PDF нет: это текст и макеты для сборки.

## Визуальное направление

- Основной цвет: оранжевый #F08331 (= `AppTokens.primary`, `frontend/lib/core/theme/app_tokens.dart`).
- Тёмный текст: по токену ARTA `#17191D` (`AppTokens.text`, `onPrimary`) — предлагаемый выбор, совпадает со скриншотами. Альтернатива по брифу — #1A1A1A. Решение за владельцем: `[ЗАПОЛНИТЬ: цвет презентации]`.
- Шрифт: Roboto (`AppTokens.fontFamily`), как в приложении. Заголовки 44–60 pt, основной текст не меньше 24 pt.
- Фон белый или #F7F8FA (`background`); акцентный фон #FFF1E6 (`primaryContainer`). Ссылки/мелкий оранжевый текст на белом — #B04A00 (`linkText`), так как #F08331 на белом не проходит контраст для мелкого текста.
- Семантические цвета из токенов: «предложено ИИ» — `suggested` #3B4BA0 на #E6E9F8; успех — #1B6B3A; предупреждение — #7A4A00 на #FFF0CC; плашка демо — #333333.
- Один слайд — одно сообщение. Скриншоты — только реальные экраны Flutter-приложения (папка `live/` отчётов устройства). Никаких стоковых картинок, иконок-украшений, мокапов, которых нет в приложении.
- Метка на каждом слайде с числами: маленький чип в правом верхнем углу («ФАКТ 2026-11-07», «ПРОЕКЦИЯ», «ДЕМО»). Цвета чипов не оранжевые, чтобы не путать с брендом.

Время ниже: «3 мин / 5 мин». Сумма: 180 с / 300 с (5 мин: 25+25+60+25+30+25+25+20+40+25).

## Слайд 2. Решение

- Заголовок: «ARTA соединяет остатки и спрос — и считает план»
- Главная мысль: каталог + проверка человеком + план распределения.
- Текст на слайде:
  - «1. Партия: фото, масса, состояние, город»
  - «2. ИИ предлагает признаки → человек подтверждает» [ИИ: PLANNED, в демо SIMULATED; подтверждение человеком: VERIFIED]
  - «3. Правила находят совместимых покупателей с причинами» [PARTIAL, только API]
  - «4. Solver делит массу: продажа, переработка, внутреннее использование. Остаток виден» [VERIFIED на малом наборе, только API; экрана нет]
  - Подпись: «Живого ИИ пока нет. ИИ не определяет состав, прочность и безопасность. План — рекомендация: он ничего не резервирует.»
- Подтверждение: `CLAUDE.md` §2, §6, §7, §8; аудит `evidence/product-capability-audit.md` п. 1–16; `docs/pitch/evidence/ai-claims-verification.md` §3 (a, b, g); `docs/pitch/evidence/optimization-claims-verification.md` «Безопасные формулировки» 1, 5, 6.
- Макет: горизонтальная цепочка из 4 блоков с чипом статуса под каждым. Блок 2 в цвете `suggested` с надписью «человек подтверждает», остальные оранжевые/тёмные. Под блоками подпись о границе ИИ.
- График: схема потока (не данные): Фото → предложение ИИ → подтверждение человеком → правила → solver → план.
- Заметки: это слайд про AI-различие (одна минута в 5-минутной версии). Сказать вслух: «ИИ ничего не подтверждает; живого ИИ пока нет». Не говорить «умный», «точный», «обученный», «живой». На вопрос «какой провайдер?» — «Не выбран `[ЗАПОЛНИТЬ: vision-провайдер]`; договорной адаптер есть, шлюза и ключа нет, живой вызов не выполнялся».
- Переход: «Покажу, как это выглядит на телефоне.»
- Время: 15 с / 25 с.

## Слайд 3. Продукт

- Заголовок: «Путь от партии до получения: что проверено и чем»
- Главная мысль: на экране только то, что имеет метку VERIFIED или PARTIAL; остальное названо отдельной строкой.
- Текст на слайде:
  - «Партия подтверждена человеком» [VERIFIED]
  - «Каталог покупателя: поиск и фильтры» [VERIFIED]
  - «Резерв: диалог «Будет удержано 12,5 кг» → статус «Передано»» [VERIFIED]
  - «Подтверждение получения → «Получено»» [VERIFIED]
  - «Заявка покупателя» [PARTIAL: в прогоне на устройстве создана через API]
  - «Прототип проверен на одном телефоне на синтетических данных; часть шагов заведена через API (debug-сборка, 2026-11-07, по отчётам). 215 + 235 автотестов по прогону 2026-11-08» [ФАКТ; число пересчитать в день выступления]
  - Плашка: «ДЕМО: данные синтетические. Живого ИИ нет (PLANNED); в демо анализ — СИМУЛЯЦИЯ. Matching, план, аналитика — только API, экранов нет.»
- Подтверждение: аудит `docs/pitch/evidence/product-capability-audit.md` п. 17, 21–23, 26–28 (VERIFIED/PARTIAL), п. 1, 2, 5 (SIMULATED/PLANNED), п. 9, 16, 25, 38 (нет экрана); `docs/pitch/evidence/demo-traction-verification.md` §2, §3.
- Макет: 4 реальных скриншота в ряд, у каждого свой чип статуса (каталог, диалог резерва, «Передано», «Получено»). Экрана анализа среди них нет. Под рядом — серая строка «Только API (без экрана): matching · план · аналитика · история сделок · внутреннее использование».
- График: скриншоты из `live/` отчёта устройства. Если экрана нет в отчёте — не рисовать.
- Заметки: здесь демо 45–60 с (`arta-demo-script.md`). Режим назвать вслух: «живой показ на подготовленном состоянии» или «запись» (резервной записи пока нет). Не показывать сумму сделки как экран. Не говорить «видите распределение» и «живой ИИ». Если спросят про план: «Расчёт на backend, покрыт тестом на малом наборе; экрана в приложении нет».
- Переход: «Теперь — с чем мы конкурируем.»
- Время: 45 с / 60 с.
