# Запись резервного видео демо на физическом телефоне

Дата: 2026-11-08. Основа: `docs/pitch/arta-demo-script.md` и `docs/pitch/evidence/demo-traction-verification.md`. Эта инструкция не запускалась: запись не выполнялась, `adb` на машине QA не найден в PATH (путь к нему нужно уточнить, см. шаг 0). Все шаги ниже надо проверить на репетиции.

Назначение: короткий клип того же сквозного прогона (продавец -> покупатель -> получение) на Xiaomi Redmi Note 14S (Android 16, debug-сборка) на случай сбоя живого показа. Данные синтетические (`*@example.test`), ИИ — симуляция. Запись называется записью, не живым показом.

## 0. Предусловия

- [ ] `adb` доступен: `adb version`. Если команда не найдена, использовать полный путь из Android SDK `platform-tools` и подставлять его ниже.
- [ ] Телефон по USB, отладка включена, `adb devices` показывает устройство в состоянии `device` (не `unauthorized`).
- [ ] Backend и PostgreSQL запущены на ноутбуке, `curl http://127.0.0.1:8000/health` отвечает; выполнен `adb reverse tcp:8000 tcp:8000`.
- [ ] Сборка запущена с `--dart-define=API_BASE_URL=http://127.0.0.1:8000 --dart-define=USE_DEMO_DATA=false`. Фиксируется режим: `[ЗАПОЛНИТЬ: API / демо]`.
- [ ] Рабочее дерево зафиксировано тегом/коммитом: `[ЗАПОЛНИТЬ: тег]` (сейчас дерево не закоммичено).
- [ ] Подготовленное состояние на свежей БД, без ручной правки БД: опубликованная партия 25 кг, Bishkek, с фото; учётки продавца и покупателя (ASCII) уже созданы. Команду сидирования указать только если она реально существует: `[ЗАПОЛНИТЬ]`.
- [ ] Свободное место на телефоне не менее 2 ГБ и на ноутбуке не менее 1 ГБ.

## 1. Подготовка телефона

1. Режим «Не беспокоить» включить (полная тишина, не «только важные»). Проверить, что значок в строке состояния виден.
2. Уведомления: отключить для Gmail, мессенджеров, SMS, звонков на время записи; убрать с экрана блокировки. Шторку очистить («Очистить все»).
3. Остаться без личных аккаунтов в кадре: выйти из лишних профилей, не открывать приложения с личными данными.
4. Автозаполнение: Настройки -> Пароли и автозаполнение -> отключить службу автозаполнения (или переключить на «Нет») и отключить сохранение паролей. Причина: DEV-07, автозаполнение предлагает чужие Gmail-адреса; плюс диалог «Сохранить пароль?» появится после входа.
5. Не ждать сна экрана: `adb shell settings put system screen_off_timeout 1800000` (30 мин) и `adb shell svc power stayon usb` (экран не гаснет на USB). После записи вернуть: `adb shell svc power stayon false` и прежний таймаут (запомнить значение командой `adb shell settings get system screen_off_timeout` до изменения: `[ЗАПОЛНИТЬ: исходное значение]`).
6. Яркость максимум, автоповорот выключен, заряд не менее 80%.
7. Часы и батарея в строке состояния допустимы; Wi-Fi и мобильную сеть можно оставить (приложению нужен только USB-туннель). Название сети не должно быть в кадре.

## 2. Проверка фокуса перед КАЖДОЙ записью

Выполнять перед каждым дублем:

```sh
adb shell dumpsys window | grep -E "mCurrentFocus|mFocusedApp"
```

Ожидается пакет приложения ARTA `[ЗАПОЛНИТЬ: package, например из frontend/android/app/build.gradle]`. Если фокус на лаунчере, системном UI (`NotificationShade`), клавиатуре, диалоге автозаполнения или другом приложении, запись не начинать: вернуть приложение, повторить проверку.

Дополнительно:
- `adb shell dumpsys power | grep -E "mWakefulness"` должно быть `Awake`.
- `adb shell dumpsys notification --noredact | grep -c "NotificationRecord"` для информации; шторку визуально убедиться пустой (скриншот шага 3 ниже).

## 3. Пробный кадр

```sh
adb exec-out screencap -p > "$HOME/Desktop/ARTA/docs/pitch/demo/_probe.png"
```

Открыть `_probe.png` и посмотреть: нет ли уведомлений, личных имён, чужих адресов, названия Wi-Fi. Удалить файл после просмотра (`rm`), если в нём что-то личное, и повторить подготовку.

## 4. Запись

Ограничение `screenrecord`: максимум 180 с за один файл. Дубль на сценарий 45–60 с укладывается; разбивать сценарий на клипы по ролям (продавец, покупатель) допустимо.

Имя файла: `arta-demo-backup_<YYYYMMDD>_<HHMM>_<режим>_<take>.mp4`, например `arta-demo-backup_20261108_1400_api_take1.mp4`. На телефоне пишем во временный каталог:

```sh
adb shell screenrecord --time-limit 90 --bit-rate 8000000 /sdcard/Download/arta-demo-backup_20261108_1400_api_take1.mp4
```

Команда блокирует терминал; запускается в отдельном окне, в другом окне выполняются действия. Порядок:

1. Выполнить проверку фокуса (§2).
2. Запустить `screenrecord`. Подождать 2 с, не касаясь экрана.
3. Идти по сценарию `arta-demo-script.md`: партия «Доступно», подтверждено человеком -> экран ИИ-анализа с плашкой «Симуляция» -> покупатель: каталог, партия «свободно 25 кг» -> заявка 12,5 кг (pending) -> продавец: подтвердить резерв (диалог «Будет удержано 12,5 кг»), передача -> покупатель: подтвердить получение (completed).
4. Закончить, подождать 2 с, остановить `Ctrl+C` в окне `screenrecord` (не убивать `adb`). Подождать 3 с, чтобы файл закрылся.
5. Скопировать на ноутбук:

```sh
adb pull /sdcard/Download/arta-demo-backup_20261108_1400_api_take1.mp4 "$HOME/Desktop/ARTA/docs/pitch/demo/recordings/"
```

(каталог `recordings/` создать заранее; он должен быть в `.gitignore`: видео в репозиторий не коммитить.)

6. Удалить файл с телефона только после проверки копии: `adb shell rm /sdcard/Download/<имя>.mp4`.

Хранение: основной файл в `docs/pitch/demo/recordings/` на ноутбуке и копия на отдельном носителе. В таблицу ниже занести путь и в `arta-demo-script.md` вместо `[ЗАПОЛНИТЬ: путь к резервному видео]`.

## 5. Известные ловушки и что делать

| Ловушка | Что видно | Действие |
|---|---|---|
| Автозаполнение Android / «Сохранить пароль?» | Выпадающий список адресов или диалог после входа; DEV-07 | Отключить автозаполнение (§1, п. 4). Если диалог появился в кадре, дубль отбросить |
| Шторка уведомлений | Свайп вниз открывает уведомления; жест часто срабатывает от случайного касания верхнего края | Включить DND, очистить шторку, касаться экрана ниже верхнего края; перед дублем проверить фокус (`NotificationShade` в `mCurrentFocus` = дубль невалиден) |
| Кнопка «Назад» уводит из приложения | Возврат на лаунчер, в кадре иконки и виджеты | Не нажимать системную «Назад» на корневом экране; навигировать вкладками приложения. Если ушли, остановить запись и переснять |
| Кириллица в `adb input text` не принимается | Поле остаётся пустым или появляются символы-мусор | Все вводимые значения ASCII; пароль не набирать (учётки сохранены/введены заранее); не использовать `adb input text` для русского. Русские надписи интерфейса в кадре — нормально |
| Экран гаснет | Чёрный кадр, блокировка | `svc power stayon usb` (§1, п. 5); проверка `mWakefulness` |
| Смена ролей на одном телефоне долгая | Выход и вход > 8 с | Сначала запись «продавец» отдельным клипом, затем «покупатель»; склейка допустима, называть это «запись того же прогона» |
| `screenrecord` обрывается через 180 с | Файл обрезан | Дубль не длиннее 90 с |
| Ошибка сервера / `adb reverse` упал | Экран ошибки сети | Остановить, переподнять `adb reverse tcp:8000 tcp:8000`, повторить дубль |

## 6. Проверка записи на отсутствие личных данных (до отправки кому-либо)

1. Просмотреть весь клип целиком на нормальной скорости, затем покадрово в местах смены экранов. Искать: уведомления, шторку, имена, фото, номера, чужие e-mail, название Wi-Fi, лишние приложения, подсказки автозаполнения.
2. Извлечь кадры раз в секунду и просмотреть их контактным листом:

```sh
ffmpeg -i <файл>.mp4 -vf "fps=1,scale=360:-1,tile=6x10" -frames:v 1 sheet.png
```

(если `ffmpeg` не установлен — просмотреть вручную; не устанавливать ничего без согласования.)

3. Метаданные: `ffprobe -show_format <файл>.mp4` (или `mdls` на macOS); убедиться, что нет GPS и имени устройства владельца. При необходимости очистить: `ffmpeg -i in.mp4 -map_metadata -1 -c copy out.mp4`.
4. Звук: `screenrecord` по умолчанию без звука; убедиться, что дорожки нет (`ffprobe` показывает только видео).
5. Виден только синтетический набор: учётки `*@example.test`, партия 25 кг, Bishkek, плашка «Симуляция». Реальные контакты в кадре = дубль отбросить.
6. Подпись при показе: «Запись того же прогона. Данные синтетические. Анализ фото — симуляция. Сервер локальный.»
7. Результат проверки записать в журнал ниже (кто проверил, дата, вердикт). Делиться файлом можно только после «ЧИСТО».
